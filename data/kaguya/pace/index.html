    PACE（電子・イオン）¶

    PACE（Plasma energy Angle and Composition Experiment）は、KAGUYAに搭載された4台の粒子分析器です。 SOPRANは公開PBF1（v3.0）を読み、4台とも同じ変数名で扱います。

    入口 センサー 測る粒子
    kg.esa1 ESA-S1 電子
    kg.esa2 ESA-S2 電子
    kg.ima IMA イオン（質量分析）
    kg.iea IEA イオン

    変数¶

    変数 次元 単位 内容
    counts time, energy, look count 生のカウント
    energy_flux time, energy, look eV/(cm^2 s sr eV) 校正テーブルでカウントから求めた微分エネルギーフラックス
    energy energy channel / eV 未校正ではエネルギーチャンネル番号、校正済みではエネルギー中心値（eV）
    quality time flag 記録の品質フラグ

    lookは検出器の視線方向の番号で、方向そのものではありません。方向（極角・方位角）を得るには 校正テーブルが必要で、下のピッチ角スペクトルはこれを使って計算します。 energy_fluxには別名eflux、differential_energy_fluxがあります。

    読み込む¶

    kg = spn.kaguya
time = spn.day("2008-01-01")

flux = kg.esa1.energy_flux.load(time)       # SopranArray
esa1 = kg.esa1.load(time)                   # 機器単位の読み込み結果

esa1.counts, esa1.energy_flux, esa1.quality
esa1.to_xarray()                            # 全変数の xarray.Dataset
esa1.to_polars("counts", reduce_look="sum") # look を合計した表
esa1.files                                  # 元ファイル
esa1.pace                                   # デコード直後のヘッダーと記録

    元ファイルを直接デコードするにはsopran.missions.kaguya.read_pace_pbf(files)を使います。 デコードはRust拡張で行い、拡張が無い環境ではPythonの参照実装に切り替わります（backend="auto"）。

    エネルギーフラックスの校正¶

    energy_fluxは次の式でカウントから求めます。

    \[ \mathrm{energy\_flux} = \frac{\mathrm{counts}}{t_\mathrm{integ}\; G\; \varepsilon} \]

    \(t_\mathrm{integ}\)は積分時間、\(G\)はPACE INFOテーブルのgファクター、\(\varepsilon\)は検出効率です。 \(\varepsilon\)の既定値0.6は、SPEDASのkgy_esa1_get3d.pro・kgy_esa2_get3d.proが使う一様な値です。 別の値を使うときはkg.esa1.load(time).to_energy_flux(efficiency=...)を呼びます。

    校正テーブル（INFOとFOV）は既定で自動的に読み込みます。取得元はSPEDASのkgy_read_inf.pro・kgy_read_fov.proと 同じ配布元で、HTTPでのみ公開されています。取得したテーブルはURLとsha256をStoreの元ファイル台帳に記録します。 テーブルが無いとenergy_fluxの読み込みは例外になり、未校正の値を返すことはありません。 校正後はenergy座標がeVの中心値になり、元のチャンネル番号はenergy_channel座標に残ります。

    cal = kg.esa1.load_calibration(download="never")   # テーブルを明示的に読む
esa1 = kg.esa1.load(time, calibration=cal)

    4台とも同じ式とテーブルの読み方で計算します。回帰テストはESA1で行っており、 ESA2・IMA・IEAのフラックスはSPEDASとの数値照合をまだ行っていません。

    欠測値65535¶

    PBF1のカウントは16ビット符号なし整数です。SOPRANは、SPEDASのPACE読み込み処理（kgy_read_pbf.pro、 kgy_esa1_get3d.pro）に合わせて、最大値65535を欠測としてNaNに変えます。 確認したPDS3ラベルにはMISSING_CONSTANTのような欠測値の宣言はありません。ゼロのカウントはゼロのまま残します。

    ピッチ角スペクトル¶

    pitch_angle_spectrum()は、校正テーブルでlookを方向に戻し、磁場とのなす角でビンに分けて time × energy × pitch_angleの配列を作ります。

    from sopran.missions.kaguya import selene_spice_kernels

b = kg.lmag.magnetic_field.load(time)                         # MOON_ME
frames = spn.FrameContext(spice_kernels=selene_spice_kernels(kg.store, time))   # 月と機体姿勢のカーネルを取得

pas = kg.esa1.energy_flux.pitch_angle_spectrum(
    time,
    magnetic_field=b,
    frame_context=frames,             # MOON_ME の磁場を PACE の視線の座標系へ回す
    pitch_bins="native",
    cache="use",
)
pas.plot()                                          # ピッチ角と時刻、エネルギーと時刻の2段
pas.energy_spectrogram(pitch=(0.0, 30.0), log_color=True)

    magnetic_field=[1.0, 0.0, 0.0]のように視線と同じ座標系の固定ベクトルを渡せば、カーネル無しで試せます。

    引数 意味
    magnetic_field 必須。PACEの視線と同じ座標系のベクトル、または座標系を持つSopranArray
    look_frame、magnetic_frame 視線（既定SELENE_M_SPACECRAFT）と磁場の座標系。異なるときはframe_contextにFrameContextを渡す
    pitch_bins "native"（4×16方向の記録は16ビン、16×64方向は32ビン。混在する日は大きい方）、ビン数、またはビン境界
    min_look_bins ピッチ角ビンに入る視線の最小数
    count_correction "none"（既定）、"event"、"trash"、"event_trash"。SPEDASの/cntcorrに相当する補正
    cache "use"なら同じ引数の結果をfeatures層に保存して再利用する

    count_correction="trash"は、捨てられたカウント（trash counter）を方位方向に配り直し、"event"は隣り合う エネルギーの組をイベントカウンターに合わせて拡大します。補正は倍率として別に持ち、生のカウントは整数のまま残します。

    結果には、記録ごとの露出時間と、pace_data_mode、pace_data_type、pace_submode、pace_svs_tbl、 pace_data_quality、record_duration_secondsの座標が付きます。ピッチ角に使える記録かどうかは 観測モードから判定しており、その規則はPACE ESAのmode判定にあります。

    イオンの3次元分布（IMA・IEA）¶

    ion_distribution()は、IMA・IEAの記録をSPEDASのkgy_ima_get3d・kgy_iea_get3dと同じ形の 3次元分布にし、記録の型ごとにPaceIon3Dで返します。

    time = spn.day("2009-02-17")
iea = kg.iea.load(time, calibration=kg.iea.load_calibration()).ion_distribution(
    count_correction="event_trash"
)
d = iea[0x81]                       # 32 energy × 16 polar × 64 azimuth
d.counts                            # (record, 32, bin)、bin = polar + azimuth × 16
d.to_units("eflux")                 # counts / rate / eflux / flux / df
d.density()                         # cm^-3
d.velocity()                        # km/s、SELENE_M_SPACECRAFT

from sopran.frames import FrameContext
from sopran.missions.kaguya import selene_spice_kernels

context = FrameContext(spice_kernels=tuple(map(str, selene_spice_kernels(kg.store, time))))
d.velocity(frame="MOON_ME", context=context)
d.directions(frame="MOON_ME", context=context)   # 各ビンの粒子の進む向き
    型 センサー 形 扱い
    0x40 IMA 4 polar × 32 energy × 1024 TOF TOFを合計。方位角なし（dphi = 360°）、幾何因子は方位角チャンネル4
    0x41 IMA 32 × 16 × 64
    0x42 IMA 32 × 4 × 16
    0x43 IMA 8 mass × 32 × 4 × 16 質量チャンネルを合計
    0x80 IEA 32 × 4 × 16
    0x81 IEA 32 × 16 × 64

    これ以外の型（IMA 0x44・0x45、IEA 0x82）はSPEDASも扱っておらず、読み飛ばした件数をnotesに残します。

    • エネルギー・角度・幾何因子はINFOテーブルから、エネルギー・極角の並び番号で配置します（angles="fov"でFOVテーブル）。 RAM表ごとに一つの格子をgridsに持ち、grid_indexで記録と対応させます。
    • theta_deg・phi_degは粒子の進む向きです。2009-02-17の太陽風で、IEAの速度をMOON_MEへ変換すると 速さの99.7%が反太陽方向でした。
    • IMAの質量チャンネルは合計し、陽子として扱います（SPEDASと同じ）。
    • 単位はkgy_pace_convert_units、モーメントはkgy_n_3d・kgy_j_3dと同じ式で、効率は0.6です（SPEDASの仮の値）。 不感時間の補正は含みません。
    • カウント補正はSPEDASの/cntcorrと同じです。IMAのevent補正にはTOFのevent 3行の和を使い、 型0x40にはtrashがないのでevent補正だけを行います。
    • SPEDASとの違い：質量チャンネルがすべて欠測のセルはNaNのままにします（SPEDASは0）。 エネルギー幅denergy_eVは絶対値にします。

    2009-02-17（太陽風）で確かめた値：IEAの速さはOMNIの0.99–1.00倍、密度は0.46–0.70倍。 昼側（SZA < 45°）のIMAでは、月から離れる向きの流束が太陽風の流束（OMNIのnv）の約0.7–0.9%。

    Parquetに保存する¶

    record = (
    kg.esa1.energy_flux.pipeline(spn.period("2008-01-01", "2008-01-03"))
    .calibrate(calibration="auto")
    .write("kaguya.esa1.energy_flux", layer="normalized", partition="day")
    .run()
)

    カウントのまま保存するときはkg.esa1.counts.pipeline(...)からcalibrateを除きます。 実行方法の詳細はバッチ処理にあります。

    制約¶

    • 保存したParquetには、lookの方向（極角・方位角）とエネルギーの座標情報をまだ含めていません。
    • ESA2・IMA・IEAのエネルギーフラックスは、SPEDASとの数値照合が未実施です。
    • ion_distribution()の密度は効率を0.6と置いた値で、IEAの太陽風密度はOMNIより3–5割小さくなります。 IMAのTOFによる質量の分離（kgy_read_tof）はまだありません。
    • data_qualityのビットの意味は公開資料で確定していないため、値はそのままpace_data_qualityに残します。
